# Context Priority Matrix

## Propósito

A Context Priority Matrix determina quais frameworks de assessment devem ser priorizados com base no contexto identificado no Intake Canvas. Nem todo contexto exige todas as camadas. Contratação demanda foco diferente de desenvolvimento pessoal, que demanda foco diferente de mapeamento de liderança. Este framework elimina o desperdício de rodar instrumentos irrelevantes e garante que os mais preditivos para o contexto sejam sempre aplicados.

A matriz cruza 5 contextos com 8 camadas de assessment, resultando em uma priorização clara: essencial, recomendado, opcional ou não aplicável.

## Quando Usar

- Imediatamente após o preenchimento do Intake Canvas
- Quando o contexto muda no meio de um assessment
- Para justificar ao solicitante por que certos instrumentos foram incluídos ou excluídos
- Na calibração do squad para revisar se as prioridades estão corretas
- Quando há restrição de tempo/budget e é preciso escolher quais camadas rodar

## Modelo / Estrutura

### Matriz 5x8: Contextos x Camadas

| Camada / Contexto | Contratação | Desenvolvimento Pessoal | Liderança | Equipe/Time | Transição de Carreira |
|---|---|---|---|---|---|
| **Traços (Big Five, Hogan, HEXACO)** | ESSENCIAL | Recomendado | ESSENCIAL | Recomendado | Recomendado |
| **Tipos/Estilos (MBTI, DISC, Birkman)** | ESSENCIAL | ESSENCIAL | ESSENCIAL | ESSENCIAL | Recomendado |
| **Motivação (Reiss, VIA, Schwartz)** | Recomendado | ESSENCIAL | ESSENCIAL | Recomendado | ESSENCIAL |
| **Forças (CliftonStrengths, VIA)** | Recomendado | ESSENCIAL | Recomendado | ESSENCIAL | ESSENCIAL |
| **Conação (Kolbe)** | ESSENCIAL | Opcional | Recomendado | ESSENCIAL | Recomendado |
| **Inteligência/Referencial (WAIS, Spiral)** | Opcional | Recomendado | Recomendado | Opcional | Recomendado |
| **Carreira (Holland, Schein, Super)** | Recomendado | Recomendado | Opcional | N/A | ESSENCIAL |
| **Papéis de Time (Belbin, Team Roles)** | Recomendado | N/A | Recomendado | ESSENCIAL | Opcional |

### Legenda de Prioridade
- **ESSENCIAL**: Deve ser incluído em qualquer assessment deste contexto. Sem isso, o mapeamento é incompleto.
- **Recomendado**: Agrega valor significativo. Incluir se tempo e budget permitirem.
- **Opcional**: Pode adicionar profundidade, mas não é necessário para um resultado válido.
- **N/A**: Não aplicável ou irrelevante para o contexto.

### Frameworks Específicos por Contexto

#### Contratação
Prioridade máxima: **Hogan (HPI + HDS + MVPI)** → **PI Behavioral Assessment** → **DISC**
- Hogan: predição de desempenho e descarrilamento em contexto corporativo
- PI: velocidade de aplicação + boa predição de fit com o cargo
- DISC: comunicação e estilo interpessoal observável
- Complementar com Kolbe se a posição exige execução específica

#### Desenvolvimento Pessoal
Prioridade máxima: **Eneagrama** → **CliftonStrengths** → **Kolbe** → **Big Five**
- Eneagrama: motivação profunda e padrões de comportamento automático
- CliftonStrengths: identificação de talentos naturais para potencializar
- Kolbe: modo natural de ação (complementa o "como" do CliftonStrengths)
- Big Five: baseline científica de personalidade

#### Liderança
Prioridade máxima: **Full Battery** (todas as camadas)
- Liderança é o contexto mais complexo: exige visão 360°
- Hogan HDS (dark side) é CRÍTICO: líderes sob stress descarrilam
- Birkman: diferença entre comportamento usual e necessidades (key para liderança)
- Motivação (Reiss/Schwartz): o que realmente move este líder?

#### Equipe/Time
Prioridade máxima: **Belbin** → **DISC** → **CliftonStrengths** → **Kolbe**
- Belbin: composição de papéis no time
- DISC: dinâmica de comunicação entre membros
- CliftonStrengths: complementaridade de talentos
- Kolbe: quem inicia, quem mantém, quem questiona, quem implementa

#### Transição de Carreira
Prioridade máxima: **Holland (RIASEC)** → **Schein Career Anchors** → **CliftonStrengths** → **Motivação**
- Holland: alinhamento interesse-ambiente
- Schein: âncoras de carreira (o que a pessoa não abre mão)
- CliftonStrengths: para onde canalizar energia
- Motivação: validar que a nova direção está alinhada com drivers internos

## Como Aplicar (step by step)

### Step 1: Receber o Contexto do Intake Canvas
- Ler Q2 (Contexto) do canvas preenchido
- Identificar o contexto primário e secundários (se houver)
- Em caso de múltiplos contextos, usar o primário como base e adicionar essenciais do secundário

### Step 2: Consultar a Matriz
- Localizar a coluna do contexto primário
- Marcar todas as camadas ESSENCIAIS como obrigatórias
- Listar as RECOMENDADAS como candidatas

### Step 3: Cruzar com Restrições (Q4 do Intake)
- Se tempo é limitado: manter apenas ESSENCIAIS
- Se budget é limitado: substituir instrumentos oficiais por proxy quando possível
- Se acesso a instrumentos é restrito: adaptar (ex: Hogan oficial → Big Five proxy)
- Documentar cada substituição e o impacto na confiança

### Step 4: Selecionar Frameworks Específicos por Camada
- Para cada camada selecionada, escolher o(s) framework(s) específico(s)
- Usar a seção "Frameworks Específicos por Contexto" como guia
- Considerar disponibilidade de normas para a população do respondente

### Step 5: Montar o Plano de Assessment
- Ordenar os frameworks na sequência de aplicação
- Estimar tempo total
- Validar com o solicitante
- Documentar justificativa de inclusão/exclusão de cada camada

### Step 6: Revisar Após Resultados Iniciais
- Após as primeiras camadas, verificar se alguma camada adicional se tornou essencial
- Exemplo: resultado de traços mostra alta neuroticism → adicionar camada de motivação para entender drivers de stress

## Critérios de Qualidade

| Critério | Indicador de Qualidade |
|----------|----------------------|
| Cobertura | Todas as camadas ESSENCIAIS do contexto foram incluídas |
| Eficiência | Nenhuma camada N/A ou Opcional foi incluída sem justificativa |
| Adaptabilidade | Substituições por restrição foram documentadas com impacto |
| Consistência | A mesma combinação contexto-camada gera a mesma priorização |
| Fundamentação | Cada priorização tem justificativa baseada em validade preditiva |

### Anti-patterns
- Rodar full battery em contexto de contratação rápida (desperdício)
- Omitir Hogan HDS em contexto de liderança (risco)
- Usar apenas DISC para contratação de C-Level (insuficiente)
- Não incluir Holland/Schein em transição de carreira (falha crítica)

## Integração com Pipeline

### Input
- **Assessment Intake Canvas** → Q2 (Contexto) e Q4 (Restrições)

### Output
- **Plano de Assessment** → lista ordenada de frameworks a aplicar
- **Confidence Scoring Model** → o número de camadas selecionadas afeta o score máximo possível
- **Cross-Framework Reconciliation** → saber quais frameworks estão no plano antecipa possíveis conflitos

### Posição no Pipeline
```
[Intake Canvas] → [Context Priority Matrix] → [Plano de Assessment] → [Execução] → [Reconciliação]
```

## Exemplos

### Exemplo 1: Contratação de Tech Lead
- Contexto primário: Contratação
- Restrições: 3 dias, budget para 2 instrumentos oficiais
- Seleção: Hogan HPI+HDS (ESSENCIAL) + PI (ESSENCIAL) + Kolbe (ESSENCIAL, proxy)
- Removido: Carreira (Recomendado, mas irrelevante para contratação interna)
- Adicionado: Belbin (Recomendado → promovido porque o Tech Lead gerenciará time)

### Exemplo 2: Coaching Executivo
- Contexto primário: Liderança + Desenvolvimento Pessoal
- Restrições: nenhuma (budget e tempo flexíveis)
- Seleção: Full battery (Liderança = todas essenciais)
- Ordem: Big Five → Hogan → DISC/Birkman → Eneagrama → CliftonStrengths → Kolbe → Motivação → Carreira
- Justificativa: construir de traços (base) até ação (topo)

### Exemplo 3: Team Building de Startup (5 pessoas)
- Contexto primário: Equipe
- Restrições: baixo budget, precisa ser rápido
- Seleção: DISC (ESSENCIAL, proxy) + CliftonStrengths (ESSENCIAL, proxy) + Belbin (ESSENCIAL, proxy)
- Removido: Traços individuais (Recomendado, mas budget não permite)
- Output: Mapa de complementaridade do time
