# Guia de Retrospectiva Pos-Assessment

## Proposito

Todo assessment deve ser validado contra a realidade. Este guia define
como conduzir retrospectivas 3-6 meses apos o assessment para medir
precisao, identificar erros e melhorar continuamente o processo.

## Quando Fazer a Retrospectiva

- **3 meses**: primeiro checkpoint — suficiente para observar comportamentos iniciais
- **6 meses**: checkpoint principal — dados de performance disponiveis
- **12 meses**: retrospectiva completa para assessments de lideranca e sucessao
- Eventos gatilho: mudanca de funcao, conflito significativo, resultado inesperado

## Estrutura da Retrospectiva

### Etapa 1 — Revisitar o Assessment Original

- Reler o relatorio completo sem olhar dados atuais
- Anotar as 3-5 previsoes implicitas mais importantes do assessment
- Identificar areas de maior e menor confianca na avaliacao original
- Registrar o que esperava que acontecesse baseado no perfil

### Etapa 2 — Coletar Dados de Realidade

**Fontes de dados**:
- Performance real no periodo (metricas, entregas, feedback de gestor)
- Feedback 360 atualizado (se disponivel)
- Observacao direta de comportamento em contextos relevantes
- Auto-relato do avaliado sobre o periodo

**Perguntas-chave para o avaliado**:
- "O relatorio do assessment ainda faz sentido para voce?"
- "O que acertou? O que errou?"
- "Algo te surpreendeu no seu proprio comportamento desde entao?"
- "As recomendacoes de desenvolvimento foram uteis?"

**Perguntas-chave para o gestor/stakeholder**:
- "O perfil descrito corresponde ao que voce observa no dia a dia?"
- "Houve surpresas — positivas ou negativas — nao previstas?"
- "As recomendacoes de composicao de equipe funcionaram?"

### Etapa 3 — Analise de Precisao

**Metricas de acuracia**:
- **Hit rate de tracos**: % de tracos que corresponderam a realidade observada
- **Precisao de previsoes**: das previsoes implicitas, quantas se confirmaram
- **Falsos positivos**: tracos/riscos identificados que nao se manifestaram
- **Falsos negativos**: comportamentos significativos nao previstos pelo assessment
- **Utilidade percebida**: nota do stakeholder sobre utilidade pratica (1-10)

### Etapa 4 — Identificacao de Erros Sistematicos

Categorias de erro:
- **Erro de framework**: instrumento nao capturou algo relevante
- **Erro de interpretacao**: dados estavam la, mas foram mal interpretados
- **Erro de contexto**: perfil correto, mas contexto mudou
- **Erro de comunicacao**: assessment correto, mas mal comunicado
- **Erro de vies**: vies do avaliador distorceu a interpretacao

### Etapa 5 — Documentacao e Aprendizado

- Registrar erros e acertos em base de dados de retrospectivas
- Atualizar guidelines de interpretacao baseado em padroes de erro
- Compartilhar aprendizados com a equipe (anonimizados)
- Ajustar calibracao pessoal do avaliador

## Template de Registro

```
ID do Assessment: [ID]
Data do Assessment: [data]
Data da Retrospectiva: [data]
Intervalo: [meses]
Hit Rate de Tracos: [%]
Precisao de Previsoes: [X de Y]
Falsos Positivos: [lista]
Falsos Negativos: [lista]
Utilidade Percebida: [1-10]
Principal Aprendizado: [texto]
Acao Corretiva: [texto]
```

## Metas de Qualidade

- Hit rate de tracos: meta > 75%
- Precisao de previsoes: meta > 60%
- Utilidade percebida: meta > 7/10
- Falsos negativos criticos: meta < 10%
